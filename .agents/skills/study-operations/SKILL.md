# Study Operations

Help the user understand a study and choose the next step. This skill supplies
planning and diagnostic guidance; it installs no tools or autonomous management
loop. Read the [operating guide](../../../docs/study-operations.md) for progress
questions and the [lifecycle reference](references/study-lifecycle.md) for setup,
feasibility/pricing, management actions or role-specific website capabilities.

## Select the interface

- To use a Cookbook recipe, follow [terac-cookbook](../terac-cookbook/SKILL.md),
  discover its actual actions and modes, then read the recipe guide. A local run
  and a Terac opportunity have distinct identities; require saved binding or
  caller evidence before associating them.
- To create a recipe, follow [recipe-creation](../recipe-creation/SKILL.md).
  Instructions and proposal YAML do not register callable MCP tools.
- For provider observations, use the available Terac tools and current schemas.
  The hosted connector requires context first. It is separate from the local
  Cookbook MCP. If unavailable, explain the setup gap or work from clearly
  labeled supplied evidence. Do not invent a universal study CLI command.

## Plan the work

Establish purpose and deliverable; ask missing participant count and audience
before creating a draft, plus duration when the user owns an external task.
Propose method, screener and other mechanics for confirmation; do not turn every
missing detail into a form. Read current tool preconditions and the lifecycle
reference before choosing feasibility-confirmed pricing or a draft-first estimate.
Use the selected recipe's input contract; Oracle's GTM brief is not universal.

Explain native uploads versus a caller-hosted collection page. Neither task
completion nor generic MCP content support proves native report acquisition.
Definition, feasibility/quote, draft review and paid launch are separate steps.
This skill proposes a setup; actual changes use a separately requested supported
workflow under the user's declared authority.

## Observe a selected study

Confirm organization/project and exact opportunity identity from context or
supplied evidence. Record source, observation time, freshness and page coverage.
Do not select a similarly named study or claim fresh reads for saved snapshots.

Use a bounded first pass: context, exact opportunity, one applicant page and one
submission page, at most four reads. One selected submission-detail read may be
added if needed, for five total. Request up to 25 rows per page where supported;
skip unnecessary reads. Report remaining pages and ask for another bounded pass
instead of silently exceeding that budget. Do not start background polling.

Use provider aggregate progress where returned, not the count of one list page.
Applicants awaiting invitation are a separate queue and may be absent from the
submission list. Partial pages provide lower bounds, not exact totals. Preserve
screening denominators, branching and quota minimum/maximum/exact meanings.
Missing values remain unknown; zero graded answers do not establish a rate.

ACTIVE indicates recruitment state, not guaranteed interest or delivery time.
Awaiting review indicates a customer decision, not automatic payment or proof
that Cookbook acquired a report. Task progress, raw report content, recommendation
and payment remain distinct. Never infer expert quality or ad performance from
submission counts.

## Explain and propose

Return observed status/target/progress, any evidenced invite or review backlog,
available screening/quota signals, coverage/unknowns and one proposed next step.
Separate facts and exact calculations from hypotheses. Include the appropriate
returned dashboard link: draft editor for draft review, submissions for progress.
A link is navigation, not evidence of status. If no link is returned, state that
it is unavailable rather than inventing one. Avoid unnecessary participant names,
contacts or profiles; keep private material and credentials outside repository files.

The initial skill observes and proposes. It does not invite/decline applicants,
change targeting/pricing, launch/pause/stop recruitment, approve/reject/pay work
or operate ads. Slow progress is not a reason to create a replacement study.
An explicitly requested change belongs to its supported workflow and declared
authority; this diagnostic skill does not grant that authority.

## Dashboard gaps

Public recruitment guidance assigns sourcing channels and pacing to Terac.
User-reported panel/Meta-ad views do not prove public campaign metrics or controls.
State which metrics were observed; ask the Terac contact about missing information
or provide a returned dashboard link for human inspection.

Computer use is optional. Use it only for explicitly requested dashboard assistance
when the host supports it; read that host's computer-use skill and confirm the
intended study before interacting. Website access grants no additional edit,
advertising or spend authority. Dashboard observations do not establish API support.

Local run inspect remains a pure saved-state read. Recipe resume advances a local
workflow within its mode; Terac opportunity resume restarts paused recruitment.
Never substitute these actions. See [skills and package contents](../../../docs/agent-skills.md)
for host discovery, Python packaging and MCP registration.
