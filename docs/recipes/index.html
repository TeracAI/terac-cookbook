Recipes

A Recipe is a runnable agent–expert workflow with understandable input, output, permitted effects and replay data. The catalog currently contains two implemented Recipes.

Oracle

Review a go-to-market brief. Oracle returns scoped feedback on buyer and pain, willingness to pay, and channel fit. The calling agent decides how to use it.

  • Identifier: oracle
  • Available modes: synthetic offline replay by default; explicitly configured live status/cost reads or opt-in feasibility/draft preparation; launch requires separate fresh confirmation
  • Callers: Python, terac-oracle, and optional local MCP
  • Input: a concise brief with its claims and evidence
  • Output: Replay returns exact-brief feedback and its limitations; live paths return bounded study, feasibility and draft observations, not expert feedback or reports
  • Cases: pass_with_comments, fail, and default inconclusive

Run Oracle · Read its feedback contract

The three cases demonstrate workflow behavior. They do not evaluate arbitrary briefs, adapt to clarification answers or establish live expert judgment.

Owner verification

Verify a small-business owner from a redacted call summary. A general-population reviewer reads a consented identity-and-intent call summary and returns verified, concerns or fail with reasons and red flags.

  • Identifier: owner_verification
  • Available modes: synthetic offline replay only
  • Callers: Python, terac-owner-verification, and optional local MCP
  • Input: a redacted call summary and an explicit recorded-consent flag
  • Output: an exact-summary verdict with reasons, red flags, three short answers and limitations
  • Cases: default verified, concerns, and fail

Run owner verification · Read its verdict contract

The cases demonstrate workflow behavior. They do not evaluate arbitrary summaries or establish anyone's identity.
